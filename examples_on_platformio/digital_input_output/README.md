# Digital Input Output

**Developed by Amine Saoud ibn al-Bashir.**

The first hardware example for NanoKit Integrated ESP32: read a push button, debounce it properly, and toggle an LED. Everything else in this repository builds on these two operations.

## Goal

Toggle an LED on every button press, reject contact bounce without blocking the program, and print the button and LED state to the PlatformIO Serial Monitor.

## What You Will Learn

- How `pinMode`, `digitalRead`, and `digitalWrite` map to real NanoKit pins.
- Why the internal pull-up makes a pressed button read `LOW`, and why that is normal.
- Why a 220 ohm resistor is needed in series with an LED on a 3.3 V GPIO.
- How to debounce a switch with `millis()` instead of `delay()`, so the loop stays responsive.
- Why acting on the press *edge* (not the level) toggles exactly once per press.

## Hardware Required

| Item | Quantity | Notes |
|---|---:|---|
| NanoKit Integrated ESP32 | 1 | Main controller board |
| Push button (momentary, normally open) | 1 | Any tactile switch |
| LED (any colour) | 1 | Optional: the onboard LED mirrors it |
| 220 ohm resistor | 1 | Current limit for the LED |
| Jumper wires | 4 | Button x2, LED x2 |
| Breadboard | 1 | Optional but recommended |

## How It Works

1. `INPUT_PULLUP` connects a weak internal resistor from GPIO4 to 3.3 V, so the pin reads `HIGH` while the button is open.
2. Pressing the button connects GPIO4 to GND, so the pin reads `LOW`.
3. Every raw change restarts a 40 ms window; a level is accepted only after it stays unchanged for the whole window.
4. When the accepted level changes to `LOW` (a press edge), the LED state is toggled once.
5. `digitalWrite` drives GPIO26 `HIGH` to light the external LED, and GPIO2 to light the onboard LED.

```bash

```

## Safety Notes

Never connect an LED directly between a GPIO and GND without a resistor; the GPIO can be damaged by the current. Never connect the button between the GPIO and 5 V: NanoKit GPIOs are 3.3 V only. With the wiring in this example the button only ever connects the pin to GND, which is always safe.
